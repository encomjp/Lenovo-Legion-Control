# Changelog - 0.2.13 (2026-09-03)

Fixes GitHub Issue #3 (reported by @Konnor378 on Legion Y7000P 16IRX9 / 83DG).

## White Keyboard Backlight Slider (Lighting)

- **Daemon-routed writes**: the white-backlight slider in `build_simple_backlight_page` no longer calls `keyboard::set_brightness()` directly from the user-space GTK process (which failed silently with `EACCES` on `/sys/class/leds/.../brightness`). Writes now go through `run_daemon_command_async(DaemonCommand::SetKbdBrightness(v))` and surface failures via `toast_error`.
- **50% steps**: the `gtk::Scale` snaps to integer steps (increment 1.0, `set_digits(0)`, round-on-drag with recursion guard, duplicate-write suppression) with marks at Off / 50% / 100% for the typical `max_brightness == 2` board; the value label shows "Off", "50%", "100%" (generic percent math for other maxima, u32 to avoid u8 overflow).

## Manual Fan Control on EC-Owned Models (Cooling)

- **Read-only fan cards**: when `fans::control_backend_name()` is `None` (e.g. Y7000P 16IRX9 / 83DG, no fan-target write path), `fan_card` renders read-only — live RPM plus an "Auto (EC controlled)" row and a "Manual fan control is not supported on this model (managed by Lenovo EC firmware)" note. The manual switch and target-RPM slider are hidden so users can no longer trigger the `no fan backend/device for target write` error toast.
- **Reset gating**: the "All fans automatic" reset group is replaced with the same EC-managed note on models without a write backend.

## Custom / User Mode Power Sliders (CPU + Home)

- **CPU → Power is live in Custom mode**: `build_cpu_power_page` no longer hardcodes `preview.set_sensitive(false)`. When the current profile is `custom`, the Custom-watts sliders are sensitive and each drag routes through `ensure_custom_then_ppt` (same Custom-gate Home uses, with direct queued-write fallback); guide text tells the user the sliders are active. Outside Custom mode they stay greyed out with the "Switch to Custom & edit" path.
- **Fn+Q sync on Home**: the Home dashboard poll now sets `ppt_box.set_visible(firmware_mode == "custom" && !ppt_scales.borrow().is_empty())` whenever the firmware mode changes, so Fn+Q directly into Custom mode immediately reveals the sliders without touching the GUI dropdown.
