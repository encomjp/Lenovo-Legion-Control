# Changelog - 0.2.16 (2026-10-14)

Security, privacy and hardware-support release, driven by fleet telemetry from 23 laptops and a survey of ~33 other Lenovo Linux projects. Tested on a Legion Pro 7 16AFR10H (83RU): 207 unit tests (also in a clean non-Lenovo container), 59/59 live hardware tests, 24/24 self-checks, and a headless GUI smoke test of all 16 pages.

## Security

- **Daemon authorisation**: hardware changes (power mode, fans, PPT, undervolt, SMT, charge limit, lighting, log level) now require root, group `legion`, or the user at the active local seat. Reading sensors stays open to everyone. Previously any local account could drive the root daemon.
- **Safer installs**: group `legion` is created before the udev rules load, and the installing user is added to it. Before, a fresh install could leave the RGB controller root-only.

## Privacy

- **Telemetry opt-out now works**: switching telemetry off in Settings (or `legion-cli diagnose disable`) now also stops the background service. Before, only the app stopped sending. Your saved choice is re-applied every time the app starts.
- Anonymous reports no longer contain your Linux user ID, Bluetooth device names or GPU process paths.

## Safety

- Known-dangerous power modes are blocked per model: `custom` on Legion Pro 7 16IAX10H (Q7CN BIOS, hard shutdown) and `max-power` on Legion Pro 5 16ARX8 BIOS LPCN65WW (power cut).
- On non-Lenovo machines the app no longer pretends to control fans or lighting.

## New

- **Fn Lock** and **Always-on USB charging** toggles (Battery page, `legion-cli fn-lock`, `legion-cli usb-charging`) where the laptop supports them.
- **New models**: Legion R9000P AFR10 (83F6), Legion 5 15IRX10 (83LY), Legion 5 15AHP10 (83M0), LOQ 15ARP10E (83S0), Legion 5 17ACH6H (82JY), plus 14 BIOS families matched at family level.
- **More keyboards detected**: every ITE lighting controller (048d:c1xx/c6xx/c9xx) is now identified from its HID descriptor. Spectrum commands are only sent when the descriptor confirms a Spectrum keyboard.

## Fixes

- Fans: the third fan is read correctly on models where it is `fan3` (legion_hwmon), EC temperatures are read from current legion_hwmon labels, and the EC-fallback layout is chosen per BIOS family. Unverified EC-fallback RPM is marked "(est.)", and a layout that reports a constant value regardless of temperature is rejected instead of showing fake ~4000 rpm.
- Fan self-checks fail honestly when no RPM backend exists, `fans_off_while_hot` needs two consecutive readings, out-of-range fan targets show as auto, and Gen 10 laptops warn that a manual fan target may persist until an EC reset.
- The app no longer wakes a sleeping NVIDIA GPU just to read sensors (better battery life on hybrid graphics).
- Speakers: a missing AW88399 firmware or driver is reported as "driver missing" with install steps, not as broken hardware. Compressed firmware files are now recognised.
- No more lighting errors on laptops without an RGB keyboard. The `spectrum_controller` self-check passes when the model has no RGB keyboard.
- "Restore last session on launch" now covers lighting too. The app used to rewrite the keyboard lighting on every start.
- NVMe temperature warnings use each drive's own limits. Battery health above 100% shows as "100% (new pack)".
- RGB repair no longer tries privileged steps from the unprivileged app.
- The daemon's settings moved from `/.config/legion-control` to `/var/lib/legion-control` (migrated automatically, same telemetry ID).
- `legion-daemon --help` prints help instead of starting the daemon.
- Settings are no longer wiped by a temporary read error.

## Build

- Releases now run `cargo test` and `cargo clippy` first, and tests pass on non-Lenovo CI runners.
